# Crackdown: where the processor time goes

Generated by `tools/hot_functions.py` from the function profiler (`--any360_profile_seconds`, `any360/host/profiler.h`: every 2 ms each running thread's stack) and a call count of the same stretch. Crackdown's city route (tools/any360-ab.ps1 input script, seconds 60-140 of play), Radeon iGPU, cores 8-15, D3D records on, 2026-11-19; 2 profile run(s) averaged.

Times are milliseconds of one core a second of play (1000 = a whole core). A function's **own** time is the time it is the innermost title function: its own code (**self**) plus the host code it calls (bindings' handlers, Any360's natives, kernel exports: the biggest one is named). A binding that only forwards leaves no frame of its own, so a bound function's time shows under its caller, in that column. **ns/call** is the own time over the calls counted. Making a function native works on its self time; the first table is the order to work in, the second shows the individually expensive ones. The `note` column is kept from one regeneration to the next: what a function is, what was done, where its numbers are.

Processor time caught running: 1133 ms a second (1.13 cores), 630 of it under title functions.
