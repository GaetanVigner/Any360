# Native D3D runtime against the title's

crackdown, 2026-11-16: the in-game self-test (`--any360_d3d_selftest=true`, docs/D3D.md) runs each function the title's way and Any360's on the same random inputs, on a copy of the device, and compares every byte they write; the times are each side's median over 8 calls in a row, the allocations each side's host heap allocations per call (bytes / allocations; the title's guest heap is guest memory). Generated by `tools/d3d_perf.py` at the end of each step; earlier steps' results are kept in `docs/perf/archive/`.

68 cases, 0 calls different; Any360 1.00x to 362.40x the title's speed (median 1.60x). Allocations measured in 68 cases: 1 allocate (Shader helper (PM4)).

In game:

- Allocations (2026-11-16): the self-test counts each side's host heap allocations a call (any360/sys/alloc_meter.h): Any360's natives allocate 0 B a call in every case but the shader helper's, where both sides show the same 0.1 B a call (the title's own helper, called by both). SetPixelShader at 1.00x (35.0 ns each side) is at the edge of the 1x rule: to optimize.
- Texture loads (2026-11-16, docs/perf/archive/2026-11-16-texture-loads): linear 1280x720 k_8 uploads 3.3-3.8 ms each before, 0.14-0.21 ms after (rows 16 bytes at a time); in the city, steady FPS 313.1 -> 325.4 (+3.9%), 10% low 271.8 -> 282.7, 1% low 220.6 -> 236.5 (+7.2%, z 2.6), the streaming dip's 1% low 128.9 -> 197.3, texture loading there 0.23 -> 0.01 ms a frame; process memory unchanged (2.91 GB). The dip's remaining 22-28 ms frames have the command processor mostly idle: the title's or any360::sys's, not the renderer's.
- D6 frame times (2026-11-15; 15 launches, 25 steady periods a variant): everything native 246.0 FPS, 10% low 212.8, 1% low 183.7; direct submission off 246.5 / 212.7 / 181.5 (no difference); native tiling off 232.8 / 197.2 / 166.2: the native tiling gives +5.7% FPS and +10.5% on the 1% low.
- D6 steps 1-6: see docs/perf/archive/ for each step's table and A/B runs.
